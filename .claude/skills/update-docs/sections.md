# Glific Docs Sections

The sidebar is autogenerated from the `docs/` directory tree (`sidebars.js`). Number prefixes on folder and file names set the order.

## Section map

| Folder | Audience | Purpose | Content type |
|--------|----------|---------|--------------|
| `2. Pre Onboarding/` | Implementation partners, technical staff | Steps to complete *before* Glific onboarding, such as setting up external platforms | Procedural guides (numbered steps, external links) |
| `3. Starter Kit/` | NGO managers | Checklists and best practices before going live | Checklists, short guides |
| `4. Product Features/` | Day-to-day users | Reference docs for every UI feature in Glific | Feature reference pages |
| `5. Integrations/` | Technical staff | How to connect and use third-party tools (OpenAI, Sheets, etc.) | Setup and usage guides |
| `6. WhatsApp Groups Automation/` | NGOs using WhatsApp Groups | Features specific to WhatsApp Groups (not 1:1 chats) | Feature and setup guides |
| `7. Use Cases/` | All users | Guides that start from a real problem and show the solution | Narrative walkthroughs |
| `8. FAQ/` | All users | Quick answers to specific how-to questions | Short Q&A pages |

## Deciding where a new page belongs

1. Is it about a UI screen or button in the Glific web app? → **4. Product Features/**
2. Is it about connecting an external service to Glific? → **5. Integrations/**
3. Is it specific to WhatsApp Groups (not regular chats)? → **6. WhatsApp Groups Automation/**
4. Is it a step required *before* going live (Gupshup, GCS, Facebook)? → **2. Pre Onboarding/**
5. Is it a real-world scenario showing how to reach a goal? → **7. Use Cases/**
6. Is it a specific question that doesn't fit anywhere else? → **8. FAQ/**

## Product Features sub-structure

Check the current layout with `ls "docs/4. Product Features/"` before choosing a number. At the time of writing:

```
01. Chats.md
02. Speed Sends.md
03. Flows/                ← folder when a feature has several pages
04. Triggers.md
05. Searches.md
06.  HSM Templates.md     ← note: two spaces in the existing filename
07. Interactive Messages.md
08. Notifications.md
09. Reporting & Dashboard/
10. Others/
11. Link Google Sheets/
Copy and Paste Node.md    ← unnumbered = legacy
...
```

Rules:
- A top-level feature gets a numbered `.md` file, using the next free number (`12. Feature Name.md`).
- A feature with several pages gets a numbered folder (`12. Feature Name/`) with numbered pages inside and a `_category_.json`:
  ```json
  {
    "link": {
      "type": "generated-index"
    }
  }
  ```
  Add `"label"` or `"position"` only if the folder name doesn't already give the right label and order.
- Unnumbered files at the end are legacy. New pages must be numbered. Don't renumber or rename existing files unless a restructure was approved, because the filename is part of the URL.
